# Capricorn V3.1.2

Release date: November 1, 2026. Complete Version `3.1.2`, Build `0052`.
Build is an independent, globally increasing four-digit release-build sequence and is not appended to the version.

## Changes

- Improves SNT reads when a disk is temporarily busy with bounded unmount retries.
- Shows clearer unmount-failure guidance and a possible occupying process to help users free the disk before retrying.

## Installation And Safety

Download `Capricorn-v3.1.2-macOS.zip` and install the stable-name `Capricorn.app`. Requires macOS 14.0 or later; includes arm64/x86_64. V2.10.2 and later support in-app upgrades; earlier versions and old development Build `1000` require manual installation.

Enable the privileged device service in Settings and complete system approval. `/Applications` is recommended; other permanent folders on local, writable, non-removable disks are supported. Disable the service before manually moving or replacing the app. In-app updates attempt to restore a previously enabled service; macOS may require renewed approval.

Each SNT read still requires confirmation before unmounting every volume on the USB device. Close files, finish other disk tasks, and back up important data first. Mount restoration is attempted afterward; failure may require reconnecting the device or using Disk Utility. Retries do not force-unmount disks or terminate processes; the displayed process is only a diagnostic clue. Removable-volume privacy consent remains separate, and background scans never initiate USB capture.

Compatibility depends on the bridge, firmware and device; not every USB device is supported, and general SD-card health queries are not provided. The reported busy state was not reproduced on a real SanDisk device for this release. No real SNT capture, volume unmount, or hardware self-test was performed.

smartctl 7.5 is bundled; SAT SMART Drive is optional. Benchmarks and workloads use temporary files in the selected folder, and write tests can stress storage.

Strict concurrency, Swift 6, universal archive, archived app launch, both architectures and matching dSYM UUIDs, and complete bundle/tool certificate signatures passed. Twenty real Sparkle fixture scenarios passed.

The app, service and tools use same-team Apple Development certificate signatures; updates use the existing Ed25519 key. Developer ID and Apple notarization are not established.

An independent universal Release build of the archived source passed. Package and feed Ed25519 signatures passed verification. Real Sparkle staging-feed checks confirmed that Build `0051` discovers `3.1.2 / 0052` and Build `0052` reports no update.

Installation regressions use isolated fixture apps, history and preferences. The service-handoff scenario uses a mock coordinator; it does not establish real root-service upgrades or retained system approval. Intel, macOS 14, and certificate trust and service approval on other Macs require separate validation.
