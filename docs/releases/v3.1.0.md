完整版本 / Complete Version `3.1.0` · Build `0050` · macOS 14.0+ · arm64 / x86_64

构建号是独立、全局递增的四位发布构建序号，不再拼入版本号。

## 中文

- 新增经系统批准的特权设备服务，供 SMART 读取、受支持的自检和手动 SNT 共用，减少重复认证。
- 支持在本地固定文件夹启用服务，应用内更新时安全停用并尝试恢复服务。
- 设置说明改为鼠标悬浮提示，拓扑补充更多 SSD 型号名称。

下载 `Capricorn-v3.1.0-macOS.zip` 并安装 `Capricorn.app`。V2.10.2 及以后支持应用内更新；更早版本或旧开发 Build `1000` 需手动安装。

在“设置 > 特权设备服务”启用并完成系统批准。App 不强制放在 `/Applications`，但必须位于本机可写、非可移除磁盘的固定目录；推荐 `/Applications`。手动移动或替换 App 前请先停用服务。应用内更新会尝试恢复此前已启用的服务，但不能代替 macOS 的重新批准，也不会启用用户从未启用的服务。

实验性 SNT 每次仍须确认卸载 USB 设备上的所有卷；请先关闭文件、结束其他磁盘任务并备份重要数据。结束后尝试恢复挂载，失败时可能需要重新连接或使用“磁盘工具”。可移动卷隐私授权仍由系统单独管理。后台扫描不会自动接管 USB 设备。

已在本机验证系统批准后的真实特权服务与外接 NVMe SMART/日志只读请求；USB-SNT 的隐私归属、接管与挂载恢复，以及硬件自检启动/中止仍需对应硬件验收。兼容性取决于桥接器、固件与设备，不保证所有 USB 设备可用，也不提供通用 SD 卡健康读取。

常规读取使用内置 smartctl 7.5，SAT SMART Drive 为可选项。测速及负载使用所选文件夹中的临时文件，请确认目标并保留备份。

App 和特权服务使用 Apple Development 证书签名，更新包及清单使用既有 Ed25519 密钥。没有 Developer ID 或 Apple 公证；首次打开及系统授权体验不能等同于已公证分发。

## English

- Adds one system-approved privileged device service for SMART reads, supported self-tests, and manual SNT, reducing repeated authentication.
- Supports service activation from permanent local folders, with safe service shutdown and restoration attempts during in-app updates.
- Moves settings explanations to hover tips and adds more SSD model names to topology.

Download `Capricorn-v3.1.0-macOS.zip` and install `Capricorn.app`. V2.10.2 and later support in-app upgrades; earlier versions or old development Build `1000` require manual installation.

Enable Settings > Privileged Device Service and complete system approval. `/Applications` is recommended but not required: the app must be in a permanent folder on a local, writable, non-removable disk. Disable the service before manually moving or replacing the app. In-app updates attempt to restore a previously enabled service, but cannot grant renewed macOS consent or enable a service the user never enabled.

Each experimental SNT read still requires confirmation before unmounting all volumes on the USB device. Close files, finish other disk tasks, and back up important data first. Mount restoration is attempted afterward; failures may require reconnecting the device or using Disk Utility. Removable-volume privacy consent remains separate. Background scans never initiate USB capture.

Real system-approved service requests and read-only external NVMe SMART/log queries have been verified on this Mac. USB-SNT privacy attribution, capture and mount restoration, and hardware self-test start/abort still require corresponding hardware acceptance tests. Compatibility depends on the bridge, firmware and device; support is not guaranteed for every USB device and does not provide general SD-card health queries.

Ordinary reads use bundled smartctl 7.5; SAT SMART Drive is optional. Benchmarks and workloads use temporary files in the selected folder. Verify targets and keep backups.

The app and privileged service use Apple Development certificate signatures; the archive and feed use the existing Ed25519 key. Developer ID and Apple notarization are not established. First launch and system approval should not be assumed equivalent to notarized distribution.

- 严格并发、Swift 6、Universal Archive 与归档 App 启动通过 / Strict concurrency, Swift 6, universal archive and archived app launch passed.
- App、特权服务、smartctl 与 SNT 工具均包含 arm64/x86_64，满足同一团队的证书签名要求，完整 bundle 签名有效；App 与 dSYM 双架构 UUID 对应 / The app, privileged helper, smartctl and SNT tool contain both architectures and satisfy the same-team certificate requirements. Full bundle signatures are valid, and App/dSYM UUIDs match.
- 20 个真实 Sparkle 隔离场景通过，包含手动/自动安装保留历史与偏好、服务衔接、任务冲突、取消、签名拒绝与启动检查 / Twenty real Sparkle fixture scenarios passed, covering manual/automatic installation with retained history/preferences, service handoff, task conflicts, cancellation, signature rejection and launch checks.

安装回归使用独立测试 App、历史与偏好，不替换真实用户 App 或数据库。服务衔接的 Sparkle 安装场景使用模拟服务协调器，不等于真实 root 服务的跨版本安装或授权保留验收。Intel、macOS 14 和其他 Mac 上的证书信任与服务批准仍需另行验证。

Installation regressions use isolated fixture apps, history and preferences without replacing the actual user app or database. The Sparkle service-handoff scenario uses a mock service coordinator; it does not establish real root-service upgrades or retained system approval. Intel, macOS 14, and certificate trust and service approval on other Macs require separate validation.
