## 中文

Capricorn V1.2.10 使用 `Version = 1.2`、`Build = 10` 和 Display Name `Capricorn V1.2.10`。本版汇总 V1.2.5 之后的改进，重点覆盖 SMART 信息展示、容量统计、外接硬盘型号识别，以及由侧边栏统一控制的实时活动和大文件负载目标。

### 下载

- Release 包名：`Capricorn-v1.2.10-macOS.zip`
- App 名称：`Capricorn V1.2.10.app`
- 系统要求：macOS 14.0 或更新版本

### V1.2.5 以来的重点更新

- SMART 页面改为可滚动布局，属性表会根据内容调整高度；最近自检记录支持折叠，状态消息可以单独清除，同时不会改变实际自检会话状态。
- 常见外接 ATA SMART 字段增加更明确的中文名称和解释。`Total LBAs Read/Written` 会优先使用 smartctl 报告的逻辑块大小换算为容量，缺失时回退磁盘清单中的块大小，并保留 LBA 数量和每 LBA 字节数。
- 侧边栏和概览新增总容量、已用和可用空间。APFS 共享容器会先去重再汇总，网络卷和多分区磁盘保留各自的可用状态，不再从缺失数据推导误导性容量。
- 新增外接机械硬盘型号目录，可从一组已验证的厂商型号编码中解析规范型号、产品系列和容量，并用于侧边栏、SMART、测速、实时活动和历史页面；无法确认的磁盘继续显示 macOS 原始名称。
- 已识别外接硬盘在侧边栏分行显示产品系列和规范型号，页面标题使用不易错误换行的组合名称；鼠标提示仍保留系统原始型号，避免隐藏底层识别信息。
- 实时活动页移除第二套磁盘选择器，监控目标完全跟随左侧侧边栏。监控或大文件负载运行期间其他磁盘行会锁定，活动磁盘消失时会停止相关任务并显示错误。
- 实时活动样本、继续监控状态、错误和历史操作按磁盘隔离。停止后切换磁盘显示该磁盘自己的状态，切回原磁盘仍可看到尚未保存的样本。
- 大文件负载默认选择当前物理磁盘中按设备标识自然排序后的第一个已挂载可写分区，也可选择同盘具体分区或文件夹。只读、未挂载、失效和跨盘目标会被拒绝或回退到自动选择。
- 负载目标按磁盘分别记忆，优先使用序列号作为持久化键；旧的全局目标只有在确认属于当前磁盘且可写时才会安全迁移。

### 安全与限制

- 写入、混合、循环和大文件负载会持续占用存储并产生写入磨损；开始前请确认目标磁盘、分区、剩余空间和供电稳定。
- 自动负载目标只使用已挂载且根目录可写的分区。跨盘文件夹不会保存，启动前 AppModel 和负载服务仍会再次验证目标归属。
- 外接型号目录只增强已验证型号的显示名称，不会把字符串匹配当作 SMART 健康、接口能力或保修结论；未知设备保留原始信息。
- Capricorn 不捆绑 smartctl，也不会自动安装或卸载 SAT 内核扩展。

## English

Capricorn V1.2.10 uses `Version = 1.2`, `Build = 10`, and Display Name `Capricorn V1.2.10`. This release collects the work since V1.2.5, with improvements to SMART presentation, capacity reporting, external-drive naming, and sidebar-controlled Live Activity and workload targeting.

### Highlights Since V1.2.5

- The SMART page now scrolls as one stable layout while the attribute table sizes to its content. Recent self-test records can be collapsed, and status messages can be dismissed without changing the underlying self-test session.
- Common external ATA SMART fields have clearer localized names and explanations. `Total LBAs Read/Written` is converted using smartctl's logical block size, with inventory block size as a fallback, while retaining the LBA count and bytes-per-LBA context.
- The sidebar and overview now show total, used, and available capacity. Shared APFS containers are deduplicated before aggregation, while network and multi-partition drives preserve unavailable states instead of deriving misleading values.
- A bundled external HDD model catalog recognizes a verified set of vendor model codes and derives canonical model, product family, and capacity for the sidebar, SMART, benchmark, Live Activity, and history views. Unknown drives keep the original macOS-reported name.
- Recognized external HDDs split product family and canonical model across the sidebar and use a grouped header name that resists awkward wrapping. Help text retains the original reported model.
- Live Activity no longer has a second drive picker. The monitored physical drive follows the sidebar, other drive rows are locked while monitoring or workload activity runs, and removal of the active drive stops related work with an error.
- Activity samples, continuation state, errors, and history actions stay isolated by drive. Switching after a stop shows the selected drive's state, and returning to the previous drive restores its unsaved samples.
- Large-file workloads automatically choose the first writable mounted partition in natural device order. Users can select another partition or a same-drive folder; read-only, unmounted, stale, and cross-drive targets are rejected or fall back to automatic selection.
- Workload choices are remembered per drive, preferring serial number as the persistence key. The legacy global folder is migrated only when it is writable and confirmed to belong to the current drive.

### Safety and Limitations

- Write, mixed, loop, and large-file workloads can sustain storage load and increase write wear. Confirm the drive, partition, free space, and stable power before starting.
- Automatic workload selection uses only mounted volumes whose root is writable. Cross-drive folders are not saved, and AppModel plus the workload service still revalidate ownership before execution.
- The external model catalog improves labels for verified model patterns; it does not turn a string match into a SMART-health, interface-capability, or warranty conclusion. Unknown devices keep their raw identity.
- Capricorn does not bundle smartctl or install/remove SAT kernel extensions.
