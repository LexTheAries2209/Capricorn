## 中文

Capricorn V2.4.2 使用 `Version = 2.4`、`Build = 2` 和 Display Name `Capricorn V2.4.2`。

### 主要更新

- 修正 USB 外壳通过 IOSAT/SAT 风格路径返回设备识别信息、但没有 SMART 载荷时被误报为已验证的问题。
- USB-SATA/USB-NVMe 透传状态现在要求实际 SMART 状态、属性、温度或健康日志；仅有桥接器类型和型号信息不会显示为成功。
- 保留桥接器诊断信息，同时明确区分“识别到访问路径”和“成功读取 SMART 数据”。

### 下载与兼容性

- Release 包名：`Capricorn-v2.4.2-macOS.zip`
- App 名称：`Capricorn V2.4.2.app`
- 系统要求：macOS 14.0 或更新版本
- smartctl 7.5 已内置，运行时不需要另外安装 smartmontools。

### 数据与安全提示

- USB 桥接器可能暴露 ATA/SAT 风格访问路径，但这不等于内部 SSD 是 SATA；SMART 是否可用仍取决于桥接器是否转发对应命令和数据。
- Capricorn 不会自动安装或卸载内核扩展，也不会自动搜索或使用 PATH/Homebrew 中的外部 smartctl。
- 测速、写入、修复和自检操作继续遵循目标确认、系统盘保护和设备能力检查。

### 验证

- 完整 macOS 测试：243 项通过，0 失败。
- Release 构建成功，App 元数据、双架构和内置 smartctl 资源已检查。
- 发布包大小：10,642,573 字节；SHA-256：`b1ce00c035cff3b26a9075bacca59239dbdacaf4dae23eb3b8967eae0b57ae94`；`unzip -t` 通过。

## English

Capricorn V2.4.2 uses `Version = 2.4`, `Build = 2`, and the display name `Capricorn V2.4.2`.

### Highlights

- Fixes false-positive verification when a USB enclosure exposes an IOSAT/SAT-shaped path that returns device identification but no SMART payload.
- USB-SATA/USB-NVMe pass-through now requires actual SMART status, attributes, temperature, or health-log data; bridge type and model identification alone cannot produce a successful result.
- Keeps bridge diagnostics visible while distinguishing transport identification from successful SMART reads.

### Download And Compatibility

- Release package: `Capricorn-v2.4.2-macOS.zip`
- App name: `Capricorn V2.4.2.app`
- System requirement: macOS 14.0 or later
- smartctl 7.5 is bundled; no separate smartmontools installation is required at runtime.

### Data And Safety Notes

- A USB bridge may expose an ATA/SAT-shaped access path without making an internal SSD a SATA device. SMART visibility still depends on command and data forwarding by the enclosure.
- Capricorn does not install or remove kernel extensions and does not search or select external smartctl binaries from PATH or Homebrew.
- Benchmark, write, repair, and self-test operations continue to use target confirmation, system-disk protection, and device-capability checks.

- Developer ID signing, notarization, and Gatekeeper trust checks are intentionally skipped; macOS may require manual approval on first launch.
