# Capricorn V2.8.0

中文发布说明：[v2.8.0.zh-CN.md](https://github.com/LexTheAries2209/Capricorn/blob/v2.8.0/docs/releases/v2.8.0.zh-CN.md)

English release notes: [v2.8.0.en.md](https://github.com/LexTheAries2209/Capricorn/blob/v2.8.0/docs/releases/v2.8.0.en.md)

发布日期 / Release date: 2026-09-21

本版为多开 Capricorn 和异常退出后的测速临时文件增加保护：同一物理硬盘上的互斥操作会在执行前检测冲突，临时文件清理继续按 runID 隔离，并安全回收过期的崩溃残留。

This release protects multi-instance Capricorn workflows and benchmark temporary files after abnormal termination. Conflicting operations on the same physical disk are detected before execution, cleanup remains isolated by runID, and stale crash leftovers are reclaimed conservatively.

## 中文

Capricorn V2.8.0 使用 `Version = 2.8`、`Build = 0` 和 Display Name `Capricorn V2.8.0`。

### 主要更新

- 新增跨进程物理硬盘操作锁。开发版与正式版共享锁命名空间，同一台 Mac 上的多个 Capricorn 实例不能同时对同一物理硬盘启动互斥操作。
- 测速、实时活动大文件负载、SMART 快速/完整自检、快速检查、深度检查、急救、装载、卸载、推出、重命名和网络卷断开均在执行前获取锁。
- 冲突检测发生在操作启动之前；发现占用时弹出提示，显示正在运行的操作和进程信息，本次操作不会继续。
- 锁以物理硬盘稳定标识协调 Capricorn 自身。它不会锁定 macOS 设备节点，也不会阻止 Finder、其他测速软件或系统服务访问硬盘。
- 保留现有 runID。当前任务只清理自己的临时文件，不再全局删除其他运行目录。
- 每个临时运行目录带有租约；新任务开始时只清理超过一小时、没有活跃租约且能确认属于 Capricorn 的残留目录，在无法确认时宁可保留。
- 进程正常结束会释放硬盘锁；进程被强制结束或系统崩溃后，操作系统会自动释放文件锁，后续实例可以继续使用同一硬盘。

### 下载、兼容性与安全

- Release 包名：`Capricorn-v2.8.0-macOS.zip`
- App 名称：`Capricorn V2.8.0.app`
- 系统要求：macOS 14.0 或更新版本
- smartctl 7.5 已内置，运行时不需要另外安装 smartmontools。
- 硬盘操作锁只处理 Capricorn 实例之间的冲突，不是系统级独占锁，也不会改变其他 App 的权限。
- Capricorn 只在选择的测速目标文件夹中创建临时文件，不直接写入裸设备。“仅读取”仍可能创建读取准备文件，不能视为零写入模式。
- 写入、混合、循环测速和实时活动大文件负载会产生存储写入和磨损，开始前请确认目标磁盘和可用空间。

## English

Capricorn V2.8.0 uses `Version = 2.8`, `Build = 0`, and the display name `Capricorn V2.8.0`.

### Highlights

- Adds a cross-process physical-disk operation lock. Development and release builds share the same lock namespace, so multiple Capricorn instances cannot start conflicting operations on the same physical disk.
- Benchmarking, Live Activity large-file workloads, SMART short/extended self-tests, quick/deep checks, First Aid, mount, unmount, eject, rename, and network-volume disconnect acquire the lock before execution.
- Conflict detection occurs before the operation starts. A conflict alert identifies the running operation and process, and the requested operation does not proceed.
- The lock coordinates Capricorn through a stable physical-disk identity. It does not lock macOS device nodes or prevent Finder, other benchmark applications, or system services from accessing the disk.
- Existing runIDs remain intact. Each task cleans only its own temporary files instead of deleting other run directories globally.
- Each temporary run directory has a lease. Before a new task, Capricorn removes only leftovers older than one hour that have no active lease and can be confirmed as Capricorn-owned; uncertain directories are retained.
- Normal process exit releases the disk lock. If a process is force-quit or macOS crashes, the operating system releases the file lock so a later instance can use the disk.

### Download, Compatibility, And Safety

- Release package: `Capricorn-v2.8.0-macOS.zip`
- App name: `Capricorn V2.8.0.app`
- System requirement: macOS 14.0 or later
- smartctl 7.5 is bundled; no separate smartmontools installation is required at runtime.
- The disk operation lock handles conflicts between Capricorn instances only. It is not a system-wide exclusive lock and does not change permissions for other apps.
- Capricorn creates temporary files only in the selected benchmark folder and never writes directly to raw devices. Read Only may still create a preparation file and is not a zero-write mode.
- Write, mixed, looped benchmark, and Live Activity large-file workloads create storage writes and wear. Confirm the target and available capacity first.
