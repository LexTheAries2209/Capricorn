# Capricorn V1.0.2

中文发布说明：[v1.0.2.zh-CN.md](v1.0.2.zh-CN.md)

English release notes: [v1.0.2.en.md](v1.0.2.en.md)

## 中文

Capricorn V1.0.2 是第一个以新版本命名原则整理的公开发布版：`Version = 1.0`，`Build = 2`，因此 Display Name 显示为 `Capricorn V1.0.2`。

### 下载

- Release 包名：`Capricorn-v1.0.2-macOS.zip`
- App 名称：`Capricorn V1.0.2.app`
- 系统要求：macOS 14.0 或更新版本

### 重点更新

- 更新为 Capricorn 命名和版本体系。
- 支持本机物理磁盘、外接 SSD、普通挂载分区、网络卷和 SD/SDXC 存储卡识别。
- 修复普通外接分区挂载点归属判断，例如 `/Volumes/40G4T_NTFS_E` 会正确映射到对应的外接物理磁盘。
- SMART 页面自适应显示属性字段，并提供固定中文解释。
- 支持同步和 POSIX AIO 异步测速引擎。
- 自定义测速最多 4 个项目组，可设置 SEQ/RND、块大小、Q、T 和混合测试。
- 实时活动页支持独立监控、采样间隔选择、大文件读取/写入/读写混合负载和历史保存。
- 历史页支持隐藏、管理隐藏记录和恢复。

### 安全提示

Capricorn 只在用户选择的目标文件夹里创建临时文件，不做裸设备写入。写入、混合、循环和大文件负载会对存储设备造成压力和写入磨损。当前 Release 资产使用本地已构建 App 打包，未通过本仓库流程自动公证。

## English

Capricorn V1.0.2 is the first public release organized around the new version naming rule: `Version = 1.0`, `Build = 2`, so the public Display Name is `Capricorn V1.0.2`.

### Download

- Release package: `Capricorn-v1.0.2-macOS.zip`
- App name: `Capricorn V1.0.2.app`
- Requirement: macOS 14.0 or later

### Highlights

- Updates Capricorn naming and version identity.
- Detects local physical disks, external SSDs, mounted partitions, network volumes, and SD/SDXC memory cards.
- Fixes mounted external partition ownership, so paths such as `/Volumes/40G4T_NTFS_E` map back to the correct external physical disk.
- SMART attributes adapt to the available data source and include stable Chinese explanations.
- Supports synchronous and POSIX AIO asynchronous benchmark engines.
- Custom benchmarks support up to 4 test groups with SEQ/RND, block size, Q, T, and mixed-test options.
- Live Activity supports independent monitoring, selectable sampling intervals, large-file read/write/mixed workloads, and history saving.
- History supports hiding, managing hidden records, and restoring records.

### Safety Notes

Capricorn creates temporary files only inside the user-selected target folder. It does not perform raw device writes. Write, mixed, loop, and large-file workloads can stress and wear storage devices. The release asset is packaged from the already-built local app and is not notarized by an automated repository workflow.
