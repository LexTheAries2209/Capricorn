# Capricorn V3.1.1

Release date: November 1, 2026. Complete Version `3.1.1`, Build `0051`.
Build is an independent, globally increasing four-digit release-build sequence and is not appended to the version.

## Changes

- Improves SMART and SNT device identification through USB hubs.
- Rejects invalid SMART responses and malformed serial numbers instead of displaying misleading health data.
- Corrects SMART target selection and the Chinese message for ambiguous devices.

## Installation And Safety

Download `Capricorn-v3.1.1-macOS.zip` and install the stable-name `Capricorn.app`. Requires macOS 14.0 or later; includes arm64/x86_64. V2.10.2 and later support in-app upgrades; earlier versions and old development Build `1000` require manual installation.

Enable the privileged device service in Settings and complete system approval. `/Applications` is recommended; other permanent folders on local, writable, non-removable disks are supported. Disable the service before manually moving or replacing the app. In-app updates attempt to restore a previously enabled service; macOS may require renewed approval.

Each SNT read still requires confirmation before unmounting every volume on the USB device. Close files, finish other disk tasks, and back up important data first. Mount restoration is attempted afterward; failure may require reconnecting the device or using Disk Utility. Removable-volume privacy consent remains separate, and background scans never initiate USB capture.

These fixes do not add SMART capability to unsupported devices. Unavailable is shown when no trustworthy response is received; previous malformed attributes are not reliable health information. Read-only identity checks passed with a real USB device through nested hubs. No real SNT capture, volume unmount, or hardware self-test was performed for this release. Compatibility of the experimental JMicron, ASMedia and Realtek protocols depends on the bridge, firmware and device; not every USB device is supported, and general SD-card health queries are not provided.

smartctl 7.5 is bundled; SAT SMART Drive is optional. Benchmarks and workloads use temporary files in the selected folder, and write tests can stress storage.

The app, service and tools use same-team Apple Development certificate signatures; the archive and feed use the existing Ed25519 key. Developer ID and Apple notarization are not established. First launch and service approval on other Macs are not guaranteed.

## Verification And Source

Full suite: 705 tests, 702 passed, 3 skipped, 0 failed. Skips cover two opt-in hardware checks and the certificate-only check on the unsigned test host. Strict concurrency, Swift 6, universal archive, archived app launch, an independent universal Release build of archived source, both architectures and matching dSYM UUIDs, and complete bundle/tool certificate signatures passed. Twenty real Sparkle fixture scenarios passed.

Package and feed Ed25519 signatures passed verification. Real Sparkle staging-feed checks confirmed that Build `0050` discovers `3.1.1 / 0051` and Build `0051` reports no update.

Installation regressions use isolated fixture apps, history and preferences. The service-handoff scenario uses a mock coordinator; it does not establish real root-service upgrades or retained system approval. Intel, macOS 14, and certificate trust and service approval on other Macs require separate validation.
